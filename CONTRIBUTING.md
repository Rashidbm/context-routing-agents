# Contributing

We welcome student and community contributions.

1. Check or open an issue, and comment before starting substantial work.
2. Create a short branch from `main`, such as `trace-sdk/events`.
3. Open a draft pull request early and link the issue.
4. Explain what changed, how you checked it, and any interface changes.
5. Ask at least one teammate to review before merging. Keep pull requests small enough to review.

Changes to the shared event or lesson schema should update `docs/architecture.md` and include a sample record. Evaluation claims should link to tasks, counts, and reproduction steps. Do not commit credentials, private traces, or personal data. Use synthetic fixtures.
